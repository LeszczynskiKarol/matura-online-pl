## 7.2 — najdłuższy ciąg zer w miesiącu

Klasyczne liczenie serii: przechodzimy dni po kolei, zwiększamy licznik przy opadach = 0, zerujemy go przy opadach > 0, po drodze zapamiętujemy maksimum. Licznik resetujemy **na granicy miesiąca**, bo pytanie dotyczy ciągu *w tym miesiącu*.

```python
from collections import defaultdict

najd = defaultdict(int)
biez = defaultdict(int)
for wiersz in open('staw.txt', encoding='utf-8').readlines()[1:]:
    data, temp, opady = wiersz.split('\t')
    m = int(data.split('-')[1])
    if int(opady) == 0:
        biez[m] += 1
        najd[m] = max(najd[m], biez[m])
    else:
        biez[m] = 0
```

## 7.3 i 7.4 — model symulacji

Dla każdego dnia, w tej kolejności:

1. **noc** — powierzchnia rośnie: `p = p * 1.0175`
2. **dzień** — amury zjadają: `p = p − liczba_amurow * 0.25`
3. **piątek** — odławianie: `p = p − 60`
4. **rano następnego dnia** — pomiar

```python
from datetime import date, timedelta

def symuluj(amury):
    p = 2000.0
    d = date(2023, 3, 1)
    maks = p
    for dzien in range(1, 185):
        p *= 1.0175
        p -= amury * 0.25
        if d.weekday() == 4:          # piątek
            p -= 60
        d += timedelta(days=1)
        maks = max(maks, p)
        if amury == 80 and p > 7500 and 'pierwszy' not in dir():
            pass
    return maks

# 7.4 — najmniejsza liczba amurów, przy której maksimum ≤ 5000 m²
print(min(a for a in range(1, 200) if symuluj(a) <= 5000))
```

## Dlaczego kontrola z 30 kwietnia jest cenna

30 kwietnia to **61. dzień** symulacji. Jeśli po tylu krokach model daje 2579 m² (25,79%), to znaczy, że i tempo wzrostu, i jedzenie amurów, i liczba piątków są policzone poprawnie. To najtańszy sposób na wyłapanie błędu przed liczeniem 7.3 i 7.4.
